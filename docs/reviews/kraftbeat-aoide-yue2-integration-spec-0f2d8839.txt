=====================================================================
1. VERDICT
=====================================================================
Incorporate it. There are two real runtimes for the files you linked, and both are source-backed. Neither has been run on your 5060 Ti.

 Route 1 (proposed primary): official yue2 package + official m-a-p/YuE2-3B and YuE2-Vae weights, in an isolated venv, driven by a KraftBeat worker process. Why primary: it is the authors' reference runtime, gives token-level progress and a cancel callback, saves reproducible artifacts (plan, tokens, latents, hashes), and does not depend on a second application.
 Route 2 (distinct optional adapter, first-class): ComfyUI + the Comfy-Org/YuE2 files (int8 convrot bundle). Source-verified in ComfyUI: YuE2 is natively implemented (nodes, model, text encoder, VAE detection, bundled-checkpoint loader), ships official workflow blueprints, and those blueprints use exactly the Comfy-Org int8 file. It has a smaller checkpoint (3.96 GB file, int8; runtime VRAM not measured, so file size is not evidence of low VRAM) and it adds a real duration control. Aoide manages its own pinned, dedicated ComfyUI server (section 7.5); it does not depend on you already running one.
 The old YuE (v1: 7B s1/s2 + xcodec) is branch YuE-v1 of the same GitHub repo. Different models and code. Not used.
 Decision rule [PROPOSAL]: build Route 1 first behind a backend-adapter interface; build Route 2 as a second adapter behind the same interface; step 0 smoke tests on the 5060 Ti decide which is the default shipped to you.

4. WHAT YuE2 DOES (capabilities by evidence type)
=====================================================================
[SRC, official package] style tags + lyrics ([Verse]/[Chorus]) -> full song, vocals + accompaniment in one stereo mix, 48 kHz. cot full (editable melody+chord ABC plan) / melody (melody plan, free accompaniment, recommended for covers) / off (no plan). Supply your own abc with full or melody. Staged API plan() -> generate_semantic() -> synthesize() -> decode(). SymbolicPlan.save/load with hash manifest. save_artifacts() writes audio.flac, score.abc, plan.json, plan_manifest.json, abc_tokens.npy, prefix.npy, semantic.npy, latent.npy, request.json, config.json, result.json (status, identity, truncated flags, sample_rate, audio_seconds, weights, timing, artifact hashes).
[SRC] Cover: SheetSage2 audio -> melody ABC, review, new lyrics/style, render cot=melody. Edit: change score.abc, re-render a NEW recording (docs say not a waveform edit).
[SRC] Official package has NO duration field. SongRequest fields are only style, lyrics, cot, seed, abc, cfg_scale, id; length follows lyrics/plan/token caps (Sampling max_tokens default 9000 for semantic). The Comfy route DOES expose max_duration (0.04 to 900 s) [SRC].
[SRC] Repo skill says YuE2 exposes no audio-reference, phoneme-alignment or local-inpainting argument. So no continuation/audio prompt/melody-audio like MusicGen-Melody, no stems or vocal-only output found.
[SRC] Instrumental: skills/yue2-music/instrumental converts the ABC (moves Vocal notes to Ins, empties lyrics) and renders. scripts/instrumentalize.py has a note-preservation gate: after conversion Vocal has 0 notes, Ins equals the merged notes, vocal pitch/onset/duration preserved, tempo/meter/key/chords checked; failures stop generation. test_tools.py has tests incl. "vocal note cannot pass instrumental gate". The skill itself says a file check is not confirmation that the audio has no vocals, and strict duration and note-for-note audio fidelity are not guaranteed. So Aoide must label this "instrumental-conditioned", not "verified vocal-free".
[CLAIM, authors' own benchmark and evaluation, not independent or peer-reviewed proof of quality] Quality competitive with Suno v5/v6 on WildSongBench (YuE2 6.7316, best-of-8 6.9632; table lists ACE-Step 1.5 at 6.0118, DiffRhythm 2 at 5.2428). Speed: 3.6-minute song in 71 s on RTX 4090 24GB with BF16, CUDA graphs, FlashAttention; peak VRAM 11.18 GiB (full cot), 24 GB host RAM recommended, 14.08 GiB at max context.
[UNVERIFIED] Everything on your hardware.

5. REQUIREMENTS AND FIT
=====================================================================
Route 1 official stated baseline: Linux, Python 3.12, NVIDIA BF16-capable GPU with 24 GB VRAM, one request at a time.
Pins in pyproject: torch==2.10.0, transformers==4.57.6, huggingface-hub==0.36.2, safetensors==0.7.0, tiktoken==0.12.0, numpy==2.2.6, soundfile==0.13.1, accelerate==1.13.0 (optional vllm extra: not used).
CUDA-optimized vs fallback [SRC]: the speed path uses CUDA graphs and fused attention (sampling.py graph_enabled only when device is cuda and not fp8; cuda_graph.py raises on non-CUDA). Code still accepts device auto -> cuda, mps or cpu and records graph_fallback_reason "non_cuda_device" so an eager CPU/MPS path exists, but no speed or quality claim covers it, and the unquantized preset requires CUDA BF16 support. Treat CPU/MPS as unvalidated diagnostic only, not a supported Aoide mode.
Memory knobs [SRC]: memory_budget_gib (sets per-process CUDA memory fraction, reserves 2 GiB), vae_core_frames 512 when budget <= 12 else 1024, offload_ar flag, quantization "fp8" (experimental, AR layers only, needs compute capability >= 8.9, disables CUDA graph). Effect of offload_ar and fp8 on speed/quality: undocumented.
5060 Ti 16GB: 4090 peak 11 GiB is below 16 GiB, unmeasured here. V100 (Volta, no BF16): the unquantized preset refuses, not a target for Route 1. Route 2 on V100, and quantized/CPU/other-device behavior of either route, are unknown (not checked), not ruled out.
Other KraftBeat engines: I did not audit whether ACE-Step/DiffRhythm/MusicGen run on DirectML/ROCm, so I make no cross-device claim about them. Aoide Route 1 is a CUDA-first feature and should show as unavailable (with the reason) on non-CUDA devices.
Disk, known sizes only: Route 1 = YuE2-3B 7.26 GB + YuE2-Vae 0.53 GB (about 7.8 GB). Cover adds SheetSage2 0.23 GB + MERT-v2-FullSong 2.53 GB (about 2.8 GB). Route 2 = bf16 bundle 7.80 GB or int8 bundle 3.96 GB; Cover adds sheetsage2_bf16 1.39 GB. Not counted/unknown: venv sizes (torch wheels), HF caches, ComfyUI install, outputs (each run also stores latent.npy and semantic.npy).
Dependency isolation [SRC]: KraftBeat requirements/base.txt has unpinned torch + audiocraft + ACE-Step git package + demucs + basic-pitch; YuE2 pins torch 2.10.0/numpy 2.2.6/transformers 4.57.6; SheetSage2 pins torch 2.8.0, transformers 4.45.2, numpy 1.24.3 (m-a-p/SheetSage2 requirements.txt). They cannot share one env. Nothing from Aoide goes into requirements/base.txt.

7. ARCHITECTURE [PROPOSAL]
=====================================================================
7.1 Adapter interface (src/aoide/backend.py): AoideBackend with is_available() -> (bool, reason), start(), submit(job) -> job_id, cancel(job_id), status events, unload(), shutdown(). Two implementations: YuE2PackageBackend (Route 1) and ComfyUIBackend (Route 2). src/models/yue2.py registers a thin MusicGeneratorBase wrapper "yue2" calling the selected backend (generate(prompt->style, lyrics, temperature->semantic sampling, seed, cot) -> ndarray [2, n] at 48000 Hz). The wrapper sets sample_rate=48000, supports_vocals=True, supports_lyrics=True, supports_continuation=False, max_duration=None.
7.2 Duration (explicit): Route 1 has no duration parameter, so the UI shows NO duration slider for it; it shows the result length after generation, and optionally an "approximate length" hint derived from lyrics only after measuring on real runs (not before). Route 2 exposes max_duration (a ceiling, "generation can stop earlier" per node tooltip) so label it "max length". No fabricated mapping from slider to sections.
7.3 Global GPU lease. Add a process-level lease in ModelManager (not just "active_loader"): acquire_gpu(owner, kind) blocks or refuses a second heavy GPU owner, including EXTERNAL child processes (Aoide worker, ComfyUI server, and any other external-process engine KraftBeat adds later, e.g. a separate transcription worker; the lease is generic and must not hard-code a project). The lease is held for the whole lifetime of the child process, from spawn until the process has actually exited (verified by process exit code), not until a Python object is deleted. Switching engines: request unload from current owner -> graceful shutdown message -> wait -> terminate -> kill -> confirm exit -> only then grant the next lease. Never assume parent-side torch cleanup frees child VRAM.
7.4 Route 1 worker protocol (src/aoide/worker_yue2.py, runs in the venv python; parent talks newline-delimited JSON over stdin/stdout; stderr is a log pipe):
 - Two threads in the worker: a reader thread that handles control messages at all times, and a generation thread. Cancel works while generation blocks: reader sets a threading.Event; the pipeline's cancelled= callable returns event.is_set() (pipeline.__call__/plan/generate_semantic/synthesize accept cancelled= [SRC]); on cancel the pipeline raises InterruptedError, worker replies cancelled, discards partial output. Cancellation latency is bounded by when the callable is polled (per token in AR; per stage/step elsewhere [UNVERIFIED which]); if no ack within a timeout, parent terminates the process.
 - Every message carries protocol version and request id = job id (UUID, plus an id passing the package's filename rule [A-Za-z0-9][A-Za-z0-9_.-]{0,179} [SRC protocol.py]). One in-flight job; a second submit while busy returns error "busy". Events echo job id; the parent drops events whose job id is not the current owner (stale/crash leftovers).
 - Commands: hello/ready (version + hashes), load(model_dir, vae_dir, budget, offload_ar), submit(job), cancel(job_id), ping, unload, shutdown. Events: stage(plan|semantic|nar|vae), progress(token count), done(artifact_dir), error(type, message, retryable), cancelled.
 - Crash/restart: unexpected exit (non-zero or no heartbeat for N seconds) -> job marked failed with exit code and last stderr lines, lease released only after confirmed exit, worker not auto-resubmitted; one automatic restart for load failures only, never replays a submitted job silently. Timeouts: load timeout, per-stage stall timeout based on progress heartbeats (not wall clock of a song), cancel-ack timeout, shutdown grace (e.g. 10 s) then terminate then kill. Concrete numbers are tunables set during step 0.
 - Logging: worker stderr and stdout are captured to a rotating KraftBeat log file; never log HF tokens, environment variables or full prompts at INFO; worker is launched with a scrubbed environment (pass only HF_HOME/cache path and HF_HUB_OFFLINE=1 after models are present). Model download is a separate explicit user-approved setup step (see section 9 for the setup and smoke-test commands), never done inside the worker.
 - Flow control: reuse the pipeline; keep it loaded between jobs until idle timeout or engine switch.
7.5 Route 2 adapter (ComfyUIBackend): v1 uses a managed, dedicated ComfyUI server only: Aoide launches a pinned ComfyUI (tag v0.41.3, commit 8713616fcc32, own venv, own models dir, started with explicit --listen 127.0.0.1 --port <free port>), owns its process and lease, and is the only client. Attaching to an existing/external ComfyUI server is DEFERRED: Aoide could not share the lease, could not terminate it, and a global /interrupt would hit someone else's jobs. Aoide never kills an unrelated process and never interrupts jobs it did not submit. Builds the API-format prompt from a pinned workflow JSON (derived from ComfyUI's own blueprints "Text to Music (YuE2)" / "Music Cover (YuE2)"), submits POST /prompt with a client-generated id, reads results from GET /history/{prompt_id} and GET /view, cancels a running job with POST /interrupt (safe only because the server is Aoide-owned and single-client) and a still-queued job with POST /queue {"delete": [prompt_id]} (master source verified; confirm at the pin in step 0, otherwise cancel-queued stays unresolved and Aoide does not claim it), frees with POST /free, and treats any node_errors or missing node classes (/object_info lacks YuE2GenerateMusic) as "ComfyUI version too old". Duration: max_duration input, then seconds output wired to EmptyYuE2LatentAudio inside the graph. The same lease (7.3) covers the ComfyUI process lifetime. Progress comes from ComfyUI's websocket (route /ws exists in server.py; message format not read); if unavailable fall back to polling /queue and history with a coarse "running" state. Remote, LAN or already-running ComfyUI is out of v1.
7.6 Deferred (label as deferred, no design now): network/socket worker or remote machine mode. It needs authentication and TLS design first. Not in v1.
7.7 Pinned runtime (Route 1). Install from source at an exact commit, not the loose 0.1.6 label: yue2-infer from git commit 1647252d68b70cbead046ffd3f7caf036dde47ee (main, 2026-10-06). Reason: I diffed the released wheel against main; the wheel yue2_infer-0.1.6-py3-none-any.whl (sha256 129a015327a2eca530760ffd2163ccb8cb65f7e601715de1d9626a40c568e2e2) differs from main in cli, fast, modeling_vae, pipeline, storage by a few lines, e.g. explicit encoding="utf-8" on file reads (matters on Windows) . The model card additionally ships 0.1.3 and 0.1.5 wheels; do not use those. Aoide records the commit, the dependency pins above, and the weight revisions (m-a-p/YuE2-3B 8f24312f..., m-a-p/YuE2-Vae 152733a1...) in its own lock file and verifies them with the package's own weights_manifest sha256 checks (pipeline verify_hashes). Dependency-wheel hashes: [UNRESOLVED, generate a hash-pinned requirements file at build time in step 0].
7.8 Artifact validation (both routes): Official route: the parent accepts a job only if artifact_dir is under Aoide's per-job output root (resolve + is_relative_to, no symlinks, matching the package's own symlink rejection); result.json exists with status "complete"; its sample_rate is 48000, audio_seconds > 0 and matches the decoded file length; artifact hashes in result.json match files; audio.flac decodes to stereo, finite, non-silent (peak above a floor); truncated flags are surfaced in the UI, not hidden (truncated abc or semantic = warning state). score.abc, if present, must parse with the native Vocal/Ins voice check before display. Route 2: ComfyUI does not write result.json, and upstream is not asked to. The parent builds its own canonical manifest (job id, route, pinned ComfyUI commit, checkpoint filename + sha256 computed locally, workflow JSON hash, inputs, seed, seconds output, timings, output file sha256) and applies the same audio checks. The output file must come from /history for the exact prompt_id, filename sanitized, copied into the job folder. Truncation flags do not exist on this route; report only measured length vs requested max_duration.

8. UI AND WORKFLOWS [PROPOSAL]
=====================================================================
New sidebar entry "Aoide" (appended; existing panels untouched; styled like ACE-Step panel). A route selector (Official package / ComfyUI int8) with availability reasons.
 1. Compose: style tags, lyrics with section tag buttons, plan mode (Full / Melody / Off), seed, Generate, Stop. No duration slider on Route 1 (7.2); "Max length" on Route 2.
 2. Score: "Plan only" saves the plan, shows score.abc, lint + compare (port the idea of skills/yue2-music/scripts/abc_tools.py: notes/timing/meter/tempo invariants), then "Render this score" re-renders as a new recording with the edited ABC as input (plan edits are new input, not in-place changes; the package forbids that [SRC]).
 3. Cover: choose audio or an existing stem, SheetSage2 transcription (Route 1: separate venv, torch 2.8.0 stack; Route 2: SheetSage2AudioToABC node), show/edit melody ABC, new lyrics/style, cot melody. Warn: transcription errors carry into the cover; review the score first.
 4. Instrumental-conditioned: plan, move Vocal -> Ins with the preservation gate, render with empty lyrics. UI text: "instrumental-conditioned, not verified vocal-free". Never show a "no vocals" badge from the symbolic gate.
Results go to the existing player; each run folder keeps artifacts so re-render with the exact plan works.

10. ACCEPTANCE AND ERROR-LIFECYCLE GATES [PROPOSAL]
=====================================================================
Gate A (before any KraftBeat code): smoke runs above produce a successful output on the 5060 Ti for at least one Route, meaning either an official-route complete result.json, or a Route 2 history output that passes the audio checks and has a parent-built canonical manifest; record numbers. If both fail, Aoide is parked with a documented reason, not shipped half-working.
Gate B (protocol, no GPU, mock worker): handshake/version mismatch rejected; busy rejection; cancel while mock generation blocks acknowledges within timeout; stale job-id events dropped; worker crash mid-job -> failed job + lease released after confirmed exit; hung worker -> terminate then kill; shutdown grace honored; stderr captured, token/env redaction test; artifact path escape (../, symlink, absolute path) rejected; tampered result.json hash rejected.
Gate C (GPU, opt-in test): short style + 2-line lyrics: 48 kHz stereo, finite, non-silent, truncated flags false or surfaced; cancel mid-generation returns control and the child VRAM is free after exit (nvidia-smi / torch.cuda.mem_get_info from the parent); unload then load another heavy engine works without OOM (lease test); repeat 3 loads/unloads with no growth.
Gate D (workflows): plan-only then render edited score: compare must separate an intentional edit (user changed notes, harmony or tempo: expect the reported differences, check only that the file parses and the Vocal/Ins structure is valid) from an invariant-preserving transformation (e.g. harmony-only reharmonization, Vocal->Ins move: notes/timing/meter/tempo must match the declared invariant, as abc_tools compare reports); instrumental conversion gate fails closed on a Vocal-containing result; cover on a short clip with SheetSage2 produces ABC that parses; ComfyUI adapter: node-missing error, interrupt, seconds->latent wiring test, server-down error.
Gate E (UI): availability reasons shown (no CUDA, no venv, models missing, ComfyUI too old); downloads are explicit and resumable and show the 7.8 GB (Route 1) / 3.96 GB (Route 2 int8) figures; no duration slider on Route 1.
Error taxonomy shown to the user: not installed / model missing / unsupported device / out of memory (suggest offload_ar or Route 2 int8) / truncated output / cancelled / worker crashed (with log path) / artifact invalid.
